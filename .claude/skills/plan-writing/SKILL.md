# Plan 模式的寫法

Plan 是給技術主管審的技術文件，寫概念與決策，不寫實作細節。包含：

- **需求**：要解決什麼問題、做完的樣子（必要時列「不做什麼」）
- **現況**：目前怎麼運作、問題出在哪（模組層級即可）
- **打算怎麼改**：方向與關鍵設計決策；有替代方案時一句話說為何不選
- **風險點與對策**
- **驗證方式**：用哪一層測試守護（unit／offline e2e／live）、怎麼確認做完
- **待決事項**：需要使用者拍板的選擇（沒有就省略）

不要寫：程式碼片段、函式簽名、逐檔逐行的改動步驟、變數命名。
提到檔案只到模組層級（例如「list_session 的狀態機」）。
篇幅以一頁內能讀完為準。實作細節留到 plan 通過後再處理。
